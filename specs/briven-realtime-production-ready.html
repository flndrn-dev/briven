Purpose

For: flndrn — to get Briven to "100% real-time production-ready" so it can be tested live with the ISY database and unblock Katsuro (and later the git platform). Not for: shipping new product surfaces (wallet, branches, workflows) — those are explicitly out of scope here. Why now: Briven is the gate for everything else on the roadmap; until its data layer and real-time loop are trustworthy, nothing built on top is usable.

Problem

"Little bugs keep coming back" and stall the build. A 4-agent audit + a live DoltGres probe proved this is not bad luck — it is one root cause with two halves:

  1. The database switch (Postgres → DoltGres) was left half-finished on purpose. apps/api/src/db/data-plane.ts still keeps two drivers (postgres.js + pg) and two tenancy models (schema-per-project + database-per-project) side by side. Old wiring survives in cold corners (metering, customer-auth, db shell, deploy triggers) and breaks the first time each is exercised.
  2. Nothing tests the real DoltGres. Every test mocks the DB or points at a dead URL; the existing tests are titled "MySQL" and 8/11 currently fail; CI runs no database and may not run at all; images ship even when tests are red. So incompatibilities are invisible until production.

Result: the same unfinished convergence surfaces one surface at a time, forever, until both halves are fixed.

Solution

Finish the convergence to ONE world, prove the real-time loop, and build a DoltGres-backed test net that runs in CI before every deploy. Concretely: (a) a foundation test harness that exercises the real DoltGres end-to-end (this stops the recurrence); (b) fix the proven incompatibilities in batches, each verified locally before a single batched deploy; (c) prove ISY's live write→update loop in production; (d) harden the reactive engine.
